## Why this matters to you
SSH keys are like digital ID cards that prove you are who you say you are when connecting to the cluster. The TReNDs cluster requires certificate-based authentication — you can't just use a password. This means you need to generate a keypair and get it signed through elpis before you can connect. This is a one-time setup that you won't need to repeat unless your certificate expires.

## What SSH keys are
SSH authentication uses public-key cryptography:

- **Private key** (`id_<campusid>`): A secret file stored on YOUR machine. Never share this with anyone. Never copy it to the cluster or email it. Think of it as the key to your house.
- **Public key** (`id_<campusid>.pub`): A file derived from the private key that you can share freely. You upload this to elpis for signing. Think of it as your lock — anyone can see it, but only your private key opens it.
- **Certificate** (`id_<campusid>-cert.pub`): Generated by elpis when it signs your public key. This is proof that the cluster administration vouches for your identity. Think of it as a notarized letter saying "this key belongs to this person."

When you SSH to the cluster, your client automatically presents the private key + certificate. The cluster verifies the certificate's signature and grants access.

## Step 1: Create the .ssh directory

### Mac/Linux
```
$ mkdir -p ~/.ssh
$ chmod 700 ~/.ssh
$ cd ~/.ssh
```

### Windows (PowerShell)
```
> mkdir $env:USERPROFILE\.ssh
> cd $env:USERPROFILE\.ssh
```

## Step 2: Generate the keypair
Replace `<campusid>` with your actual CampusID (e.g., `jsmith42`):

```
$ ssh-keygen -f id_<campusid>
```

When prompted:
- **Passphrase**: You can set one for extra security (recommended) or press Enter for none. If you set a passphrase, you'll need to enter it every time you SSH (or use ssh-agent to cache it).

This creates two files:
- `id_<campusid>` — your private key (keep this safe!)
- `id_<campusid>.pub` — your public key (you'll upload this)

## Step 3: Display your public key
You need to copy the public key text to paste into elpis:

### Mac/Linux
```
$ cat ~/.ssh/id_<campusid>.pub
```

### Windows (PowerShell)
```
> Get-Content $env:USERPROFILE\.ssh\id_<campusid>.pub
```

Copy the entire output — it starts with `ssh-rsa` or `ssh-ed25519` and is one long line.

## Step 4: Sign the key on elpis
1. Go to [https://elpis.rs.gsu.edu/](https://elpis.rs.gsu.edu/)
2. Log in with GSU credentials
3. Navigate to the SSH key signing section
4. Paste your public key text
5. Submit for signing
6. Download the certificate file (`id_<campusid>-cert.pub`)

## Step 5: Install the certificate
Move the downloaded certificate to your .ssh directory:

### Mac/Linux
```
$ mv ~/Downloads/id_<campusid>-cert.pub ~/.ssh/
$ chmod 600 ~/.ssh/id_<campusid>*
```

### Windows (PowerShell)
```
> Move-Item $env:USERPROFILE\Downloads\id_<campusid>-cert.pub $env:USERPROFILE\.ssh\
```

## Step 6: Add the key to ssh-agent
The ssh-agent caches your key so you don't need to specify it every time:

### Mac/Linux
```
$ eval $(ssh-agent)
$ ssh-add ~/.ssh/id_<campusid>
```

### Windows (PowerShell)
Make sure the ssh-agent service is running:
```
> Get-Service ssh-agent | Set-Service -StartupType Automatic
> Start-Service ssh-agent
> ssh-add $env:USERPROFILE\.ssh\id_<campusid>
```

## Verify your files
You should now have three files in `~/.ssh/`:
- `id_<campusid>` — private key (permissions should be 600)
- `id_<campusid>.pub` — public key
- `id_<campusid>-cert.pub` — signed certificate

## Certificate expiration
Certificates from elpis expire periodically (typically every 6-12 months). When your cert expires, SSH connections will fail with an authentication error. To renew:
1. Go back to elpis
2. Re-sign your existing public key (no need to generate a new keypair)
3. Download and replace the cert file
